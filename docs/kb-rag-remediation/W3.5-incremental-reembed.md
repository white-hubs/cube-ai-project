# W3.5 — 文档 checksum 与增量 re-embed（原报告 R-07 缺口）

> 来源：plan-review G-07。2026-08-10 实现复核将“避免重复 embedding”和“避免重复 parse”拆开：当前工作区实现前者，后者缺少 chunking/config fingerprint，不能仅凭文件 checksum 安全跳过。

## 1. 背景与问题

审查报告 R-07 要求「文档版本/checksum 增量 re-embed，避免全量重导」。
W3.1–W3.4 未覆盖；W3.1 仅把「实时 CDC」列为非目标。

## 2. 目标 / 非目标

**目标**

- 文档级 content checksum（文件字节或规范化文本）
- chunk 级 embedding fingerprint（embeddingText hash + modelCode + instruction profile + algoVersion）
- payload 版本由不可变 generation 承载；ACL、metadata、tenant/document scope 变化创建新 generation
- reindex 时：完成 parse/diff 后仅变更 chunk 重嵌；未变 chunk 从旧 point 复用向量
- 与 W3.3 队列兼容（任务可带 `forceFull=false`）

**非目标**

- 实时 CDC / binlog
- 跨模型自动全量迁移（换 embedding 模型时显式 full reindex）

## 3. 设计要点

1. `document.content_checksum` / `document.embedding_model_code`
2. `document_chunk.embedding_fingerprint` + `generation_id`；如将来允许同 ID 原地 payload 更新，再加独立 `payload_fingerprint/version`
3. `reindexDocument({ forceFull?: boolean })`：
   - 默认：parse → diff chunks → 新 generation；只 embed 变更 chunk，复用未变向量
   - forceFull：走现有全量路径（W3.1）
4. 换模型：检测 modelCode 变化 → 强制 full
5. **fingerprint 版本位（必须）**：
   `embedding_fingerprint = hash(embeddingText + modelCode + instructionProfile + algoVersion)`
   `algoVersion` 为常量（如 `v1`）；分块/前缀算法变更时 bump → 自动全量或按文档重嵌
6. metadata/ACL 变化不能被 content checksum early-return：embedding 可复用，但必须建立完整新 generation，并在双腿就绪后 CAS 切换
7. 仅当同时持久化并比对 source checksum、chunking config fingerprint、normalizer/parser version、embedding model/algo version 时，才允许在 parse 前直接跳过。当前没有完整 config fingerprint，因此 checksum 只用于审计/观测，不作为“文件未变就直接返回”的充分条件。

### 3.1 设计约束 / 扩展点

- **约束**：embedding fingerprint 必须含 **algoVersion**；payload 用不可变 generation 隔离，不能用“无需重嵌”推导“无需更新 Qdrant”
- **扩展点**：W3.3 任务字段 `forceFull`；换模型 / bump algoVersion → 强制 full
- **反模式**：仅比文件 mtime 决定是否重嵌

## 4. 实现步骤

- migration：content checksum、embedding fingerprint、generation ID
- ingest 计算 embedding 指纹；metadata/ACL 更新创建新 generation
- reindex diff 算法
- 单测：未变更 chunks 的 reindex 调用 embed 次数为 0（仍允许 parse）
- 单测：改一个 chunk 只重嵌一条
- 单测/E2：仅 ACL/metadata 变化不调用 embed，但建立并激活新 generation
