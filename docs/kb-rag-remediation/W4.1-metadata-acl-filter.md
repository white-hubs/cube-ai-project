# W4.1 — 文档元数据过滤与 ACL pre-filter（F-05 / F-10）

> 修订说明（对照 plan-review G-03）：ACL **必须同时**作用于 Qdrant 向量腿与 MySQL 词法腿，否则词法召回会越权泄漏。

## 1. 背景与问题

检索过滤以 `tenantId` 为当前强制安全边界，并支持 `documentId` / `directoryId`。当前业务语义是同租户所有已认证用户可见全部租户文档；组 ACL 仅作为未来扩展，不是本轮产品必需能力。
检索是双腿：`Qdrant` + `searchLexicalChunks`。只滤 Qdrant 时，无权限文档仍可经词法腿进入 `mergeRecallResults`。
报告 F-05 / F-10 Major。

## 2. 目标 / 非目标

**目标**

- 文档级可检索 metadata：`docType` / `lang` / `tags` / `createdAtFrom` / `createdAtTo`
- 自定义 metadata 本轮只存储，不开放任意键检索；否则无法预先建立 Qdrant payload index，也无法定义类型、比较语义和查询成本
- 文档级 `aclGroupIds`（或等价）写入：
  - Qdrant point payload
  - MySQL `document` / `document_chunk`（词法可过滤）
- Search API filter（AND 等值/包含）
- KnowledgeQuery 从平台已验证 principal/claims 解析 `allowedGroupIds`；不得在 kb-core 自行把任意 userToken 字符串当身份
- **无权限文档在向量腿与词法腿均不可见**

**非目标**

- chunk 级密级
- 跨租户共享 ACL
- namespace-per-tenant shard（F-15 演进，见非目标）

## 3. 设计要点

### 3.1 双腿过滤（必须）

| 腿 | 改动点 |
| --- | --- |
| Qdrant | `buildSearchFilter` 增加 acl / metadata must（或 should+min_should） |
| MySQL 词法 | `DocumentChunkRepositoryOrm.scopeFilter` 或 `searchLexicalChunks` WHERE 增加 acl 条件（如 JSON_OVERLAPS / 桥接表） |

验收：**故意只在词法侧可命中的无权限文档不得出现在结果中**。

### 3.2 写入

- ingest/index：document metadata + acl → 每个 chunk 行 + 每个 Qdrant payload
- 旧数据兼容期：**租户内可见**；新文档强制打标（选定）

**兼容期策略（SEC-01 已决策）**

- `NULL`/空数组 → **租户内可见**，与当前产品语义一致。
- 保留已有 ACL 列和可能存在的测试数据，不做破坏性 migration，也不额外引入 visibility enum。
- 非空 `aclGroupIds` → 必须与服务端 `resolveAllowedGroupIds(identity)` 结果有交集；无交集（含调用方无组）→ **双腿拒绝**（fail-closed for tagged）。
- 非空组 ACL 是兼容/实验扩展，不作为当前 release gate；没有可信 group claims 时不得自行从 opaque token 推断组。
- 更新 metadata/ACL 后，通过新 generation 复用旧向量（embed=0），先完整写入 MySQL chunk 与 Qdrant payload，再用同一 MySQL 条件更新原子切换 active generation 和 document metadata。检索结果以 MySQL active generation 二次校验，不能只写“稍后 reindex”。

### 3.3 API

```json
{
  "query": "...",
  "filters": {
    "createdAtFrom": "2026-01-01T00:00:00.000Z",
    "docType": "standard",
    "tags": ["消防"]
  }
}
```

ACL 不由客户端传「我想看哪些组」，而由服务端身份解析后强制注入。删除把任意 `userToken` 当 JSON 解析组声明的路径，也拒绝调用方直接覆盖 `allowedGroupIds`。
客户端传 `filters.allowedGroupIds` / `aclGroupIds` / `groupIds` → **400**。
未知 filter 字段也返回 400，不得静默忽略后给调用方造成“已过滤”的假象。

身份契约：tenant、subject、groups 来自 verified principal 或受信 port context；原始 Bearer/API key/tenant header 的存在不构成认证/授权。API key 的记录租户不得被请求头扩大。

### 3.4 设计约束 / 扩展点

- **约束**：双腿缺一不可合；ACL 由服务端注入，禁止信任客户端 `allowedGroupIds`
- **扩展点**：`resolveAllowedGroupIds(identity)`（或等价）为唯一 seam——换平台身份源只改该函数，不改 Qdrant/MySQL 过滤拼装
- **反模式**：只滤向量腿；在 controller 复制两套 ACL if

### 3.5 落库与反规范化

- Migration `V004__document_metadata_acl.sql`
- `document_record`: `doc_type` / `lang` / `tags_json` / `acl_group_ids_json` / `metadata_json`
- `document_chunk`: 反规范化 `doc_type` / `lang` / `tags_json` / `acl_group_ids_json` / `doc_created_at`（词法腿单表 WHERE，避免 join explosion）
- Qdrant payload: `aclGroupIds` / `docType` / `lang` / `tags` / `createdAt`

在发送 filter 前，为 tenantId、documentId、aclGroupIds 以及实际启用的 metadata filter 创建正确类型的 Qdrant payload index。Qdrant Cloud strict mode 可能拒绝未索引过滤，OSS 也存在性能风险；官方依据见 [ROLLOUT-AND-MIGRATION.md](./ROLLOUT-AND-MIGRATION.md) §2。

## 4. 实现步骤

- DB migration：document/chunk metadata + acl（`packages/kb/core/migrations/V004__document_metadata_acl.sql`）
- SEC-01 与 verified principal/group claims 契约评审
- Qdrant payload index 创建、schema 检查与 strict-mode smoke
- 同步 Qdrant payload + MySQL 行
- Qdrant filter
- **MySQL searchLexicalChunks ACL/metadata filter**
- search / by-directory / KnowledgeQuery 接线
- 单测：向量腿拒绝无权限
- 单测：**词法腿拒绝无权限**（G-03）
- E2：ACL 收紧时任一腿失败仍 fail-closed；合法 API key 不能切其他 tenant
- 兼容期文档说明

## 5. 验收

| 用例 | 期望 |
| --- | --- |
| 无权限 + 仅向量相似 | 不返回 |
| 无权限 + 强词法命中 | **不返回** |
| 有权限 + filter 命中 | 返回 |
| 旧数据兼容期 | 行为符合选定策略 |
