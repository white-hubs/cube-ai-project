# KB / RAG 评测与收益证明策略

> 本文定义“什么证据足以证明检索改造有效”。指标代码存在、合成用例通过、代码已合并，均不等于线上收益成立。

## 1. 结论类型

计划、PR 和交付报告中的结论必须标注为以下一种：

| 标签 | 含义 | 可用于什么结论 |
| --- | --- | --- |
| **事实** | 可由代码、CI、配置快照、数据库查询或可复现实验直接核对 | 描述当前状态 |
| **推测** | 有间接证据，但仍依赖部署、流量或外部系统前提 | 提出待验证风险，不得宣称完成 |
| **决策** | 产品/安全/运维主动接受的目标、阈值或风险 | 必须记录 owner、日期和依据 |
| **主观判断** | reviewer 的工程评价 | 不能代替门阀证据 |

涉及百分比、延迟、成本和容量的结论必须同时给出样本数、时间窗口、环境、版本和计算口径；缺任一项时只能标为“待测”。

## 2. 四级证据

| 等级 | 名称 | 必须经过的链路 | 可阻断什么 |
| --- | --- | --- | --- |
| E0 | 指标单测 | 人工 hits → metrics | 只阻断指标公式回归 |
| E1 | 确定性检索契约 | `RetrievalService` → 确定性 store/provider adapter → 排序结果 | 阻断代码级排序/过滤回归 |
| E2 | 数据面集成 | 真实 MySQL + Qdrant + migration + 检索服务 | 阻断 schema、协议、双腿过滤和一致性错误 |
| E3 | live shadow/canary | 目标环境、真实或经批准的脱敏语料、真实模型 | 决定 feature flag 是否扩大或默认开启 |

约束：

- E0 可以注入 fake hits；E1 的 runner **不得**直接注入最终 hits，必须经过生产检索编排。
- 合成 fixture 的最低用例数只用于覆盖面检查，不代表统计充分。
- rerank、FULLTEXT 的收益只能由 E3 证明；E1/E2 只证明行为和安全不退化。KB 内 query rewrite/contextual prefix 已取消，不得把未启用能力计入收益。

## 3. 基线顺序

所有检索行为改动遵循：

1. 固定数据集版本、配置、模型版本和代码基线。
2. 在改动前运行 E1；具备目标环境时同时登记 E3 基线。
3. 再实施 W1.1/W1.2/W2.2/W3.4/W4.3。
4. 在相同数据、相同环境和相同流量切片上运行 after。
5. 保存原始逐 query 结果，不只保存宏平均。

因此 W1.4 是 W1.1/W1.2 的前置门阀，不再放在二者之后才首次登记基线。

## 4. 数据集与分层

数据集至少覆盖：semantic、entity、navigation、table、短关键词、长问句、直接答案与仅主题提及 hard-negative、无答案、ACL 拒绝、跨文档和长文档。每条 case 必须包含来源、期望相关项、grade、所属 segment 和脱敏状态。问答用例不能只标“相关/不相关”，还必须区分“直接完整回答、部分回答、仅提及主题”，否则无法发现高语义相似但不可回答的 Top1。

必须单列以下集合：

- **critical set**：安全、法规、关键导航等不得退化的用例；逐条验收，不以宏平均抵消。
- **quality set**：用于 hit@k、MRR、nDCG 和排序收益。
- **negative set**：无相关结果、越权文档、错误租户、恶意 filter 等。

首版 `≥10` 条只作为 CI smoke 下限。是否足以用于收益决策不得由该数字推导；E3 样本规模由 EVAL-01 决策登记，并报告不确定性。

## 5. 指标与统计口径

- 主指标只能预先选一个：hit@3、MRR 或 nDCG@k；其余为次指标。
- hit-rate 同时报告样本数和 95% Wilson 区间。
- MRR/nDCG 的差值报告按 query 配对 bootstrap 95% 区间。
- 同时报告 critical set 逐条结果、无答案误召回率、ACL 泄漏数。
- 质量指标不得脱离 p50/p95/p99 延迟、错误率、降级率、模型调用量和估算费用单独决策。

`+3%` 不是自然定律。若采用该阈值，必须在实验前由产品 owner 明确它是绝对百分点还是相对提升，并登记非劣界、成本和延迟预算；否则保持 `TBD`，不得在 PR 中临时改口径。

## 6. 合并门阀与启用门阀

### 6.1 代码合并

- E0/E1 全绿；涉及 MySQL/Qdrant 的改动需 E2 门控用例或明确的 testcontainers 运行证据。
- before/after 使用同一 dataset version；PR 附逐 segment 表。
- 任何 critical case 退化、ACL 泄漏或跨租户命中均拒合。

### 6.2 小流量启用

- E3 基线存在；实验参数、目标租户、停止条件和负责人已登记。
- 质量不低于预先登记的非劣界；错误、延迟和成本不超预算。
- 发生 ACL 泄漏、数据不可恢复分叉或错误率超过停止条件时立即关闭 flag。

### 6.3 默认开启

- 至少完成一次可复现 canary，并保存原始结果、配置快照和观察窗口。
- 负责人书面确认收益、成本和残余风险；仅有 fixture 满分或 mock provider 结果不得默认开启。
