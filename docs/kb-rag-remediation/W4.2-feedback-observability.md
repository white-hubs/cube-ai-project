# W4.2 — 反馈闭环与检索观测（F-08 / F-02 延伸）

## 1. 背景与问题

已有 `recall_count` 与 grounding prefetch 事件，但无用户反馈（thumbs / wrong_citation / missed_source），无评估仪表。
报告 F-08；W1.4 只解决离线 golden。

## 2. 本轮决策

当前产品没有 thumbs up/down、wrong citation 或 answer missing 的真实入口，也没有已确认的 feedback 消费方。先造完整 HTTP API、表和仪表会形成无分母、无 owner 的“数据闭环”假象。

- 本轮保留并加强操作观测：检索延迟、错误、召回数、rerank 超时/降级、队列深度与失败。
- 用户反馈 API、dashboard、comment 存储和 Agent feedback port 暂缓，等产品入口与数据 owner 确认后单独立项。
- `KB_SEARCH_FEEDBACK_ENABLED` 默认改为 `false`；关闭时不得挂载或接受 feedback 路由。
- 删除 `resolveFeedbackAuthFromHttp` 的 header-shape authentication：Bearer/API key header 的存在不等于身份已验证。

## 3. 后续准入条件

未来实施前必须同时具备：

- 明确的产品入口与用户行为定义；Feedback API：`POST /kb/search/feedback`（或 agent 事件旁路）
  - 类型：`thumbs_up` / `thumbs_down` / `wrong_citation` / `missed_source`
  - 载荷：`traceId` / `query` / `hit chunkIds` / 可选 comment
- 落表可查询
- 最小仪表：按日聚合反馈率 + top 差查询；分母来自检索曝光事件，不用“反馈条数”冒充反馈率；消费 `recall_count`
- 记录 retrieval/config/model/experiment version，使反馈可归因
- 可选：RAGFlow 风格 Hit Testing 只读页（内部）

后续仍非目标：

- 自动根据反馈改权重的闭环 ML
- 完整 BI 平台

### 2.1 设计约束 / 扩展点

- **约束**：feedback 写入与聚合查询解耦；`traceId` 与检索/W1.4 live 字段对齐
- **权限**：submit、按 trace 查询、租户聚合 metrics 分别定义 scope；verified principal 是唯一 HTTP 身份来源
- **数据治理**：comment 可能含敏感信息，须定义长度、脱敏/审计、留存和删除策略（SEC-02）
- **抗偏差/滥用**：去重/限流，区分曝光、提交和有效反馈；不得把自选择点踩率直接解释为总体质量
- **扩展点**：事件旁路（agent）与 HTTP API 共用同一 repository
- **反模式**：用反馈自动改检索权重且无 feature flag / 无 golden

### 2.2 Trace 关联约定（W4.2-H3）

| 来源 | 字段 |
| --- | --- |
| `KnowledgeQueryRequest.traceId`（contracts） | 权威名 `traceId` |
| HTTP `POST /kb/search` | body.`traceId` 或 header `X-Trace-Id` → 响应回显 `traceId` |
| Feedback `POST /kb/search/feedback` | body.`traceId` 必须与上述检索调用相同 |
| 落库 | `search_feedback.trace_id` + `tenant_id` |

服务端应把反馈与已存在的 `(tenantId, traceId)` 检索曝光关联；客户端自报 query/hitChunkIds 只作为待校验输入，不能覆盖服务端事实。至少记录 retrievalVersion、modelCode/configVersion、feature flags 和 subject/API key identity（按隐私策略最小化）。

## 4. 后续实现步骤

- schema + repository：feedback、search exposure、retrieval/config/model/experiment version
- HTTP API + verified principal 权限：submit/list/metrics 分离，拒绝匿名、错租户和越权聚合读取
- agent 工具/事件挂钩（`KnowledgeFeedbackPort` + `KnowledgeFeedbackPortImpl`，共用 repository）
- 导出查询或简单 HTML/内部 API（`GET /kb/search/feedback/metrics`：按日率 + top 差查询 + recall_count）
- 与 W1.4 live 评测共用 trace 字段（`traceId` 约定 + search 回显）
- SEC-02：comment 留存/删除、限流、去重和数据 owner
