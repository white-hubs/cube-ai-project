# W2.1 — llm-core：实现 openai_rerank / qwen3-rerank（F-01 依赖）

> 原计划以 Jina 为生产路径；产品决策改为 **DashScope OpenAI 兼容 `qwen3-rerank`**（已确认，见 [ADR-0037](../adr/ADR-0037-kb-rerank-qwen3-dashscope.md)）。
> 文件名保留 `W2.1-jina-rerank-provider.md` 以免破坏目录引用；内容以本文为准。

## 1. 背景与问题

Catalog 曾登记 `endpoint_type: jina_rerank`，且 chat factory 对 rerank 类 endpoint **直接 throw**。
没有独立 `RerankPort`，W2.2 无法接模型精排。

生产路径定为：

- 模型：`qwen3-rerank`（文本 RAG）
- 协议：阿里云百炼 **OpenAI-compatible** `POST /compatible-api/v1/reranks`；catalog 保存完整 endpoint，adapter 不推断或追加路径
- 当前初始化目录地址：`https://llm-rsqnz4dqml5koq8p.cn-beijing.maas.aliyuncs.com/compatible-api/v1/reranks`（北京地域、工作空间专属域名）
- Body：`{ model, query, documents, top_n? }`。`instruct?` 是 vendor 可选参数；阿里云当前文档明确省略时默认采用问答检索，因此当前 adapter 不重复发送同一默认值，也不把它加入跨域 contracts。只有明确改变排序任务、完成对应 E3 并由独立 endpoint/adapter 能力承载时才允许配置不同指令。
- Response：`{ results: [{ index, relevance_score }] }`

外部事实依据：阿里云当前官方 [Reranking API](https://help.aliyun.com/en/model-studio/rerank) 确认 `qwen3-rerank` 的 OpenAI-compatible `/reranks` 路径，并列出最大 documents、单项 token 和单请求 token 限制。该页面会随供应商更新，启用时须保存核对日期和目标地域配置，不能把计划抄录值当永久契约。

**暂缓**：`qwen3-vl-rerank` 使用另一套原生协议：完整路径为 `/api/v1/services/rerank/text-rerank/text-rerank`，请求为 `model + input{query,documents} + parameters{top_n,...}`，响应结果在 `output.results`。它不是 `openai_rerank` 换一个 URL 即可兼容，多模态 contracts 与 adapter 留到 W4.4；当前若误配为 `openai_rerank` 必须明确拒绝。

## 2. 目标 / 非目标

**目标**

- 实现 OpenAI 兼容 Rerank HTTP 客户端（`POST …/reranks`）
- 通过 catalog runtime config（apiBaseUrl / apiKey / modelCode）驱动
- 新增 endpoint type `openai_rerank`；seed `qwen3-rerank`（dashscope / 阿里云百炼）
- 在 contracts 增加 **独立** `RerankPort`（不把 rerank 塞进 chat）
- 单测：mock fetch；错误映射到现有 `LlmProviderError` 类别
- provider 根据 vendor 当前限制校验 documents/token 预算；明确截断、拒绝或分批语义，不静默丢候选
- `jina_rerank` 保持未支持（路径为 `/v1/rerank` 单数，不强制共用）
- backlog 勾选对应项

**非目标**

- 不在本 PR 改 kb RetrievalService（W2.2）
- 不实现 Cohere/BGE/Jina 多协议（可留 adapter 接口扩展点）
- 不做 `qwen3-vl-rerank`
- 不做计费/限流产品面

## 4. 设计

### 4.1 contracts

`packages/contracts/src/platform/rerank.ts`：

```ts
export interface RerankRequest {
  modelCode: string;
  query: string;
  documents: string[];
  topN?: number;
  tenant: number;
}

export interface RerankResultItem {
  index: number;             // 原 documents 下标
  relevanceScore: number;    // 上游原值；W2.2 再决定 clamp
}

export interface RerankPort {
  rerank(req: RerankRequest, signal?: AbortSignal): Promise<RerankResultItem[]>;
}
```

DI token：`AGENTIC_PLATFORM_RERANK_TOKEN` = `Symbol.for("agentic.adapter.platform.rerank")`。

### 4.2 llm-core 实现

- `OpenAiCompatRerankProvider`：读 runtime config，严格向 catalog 的完整 endpoint 发 HTTP，不依据模型名或 URL 后缀推断路径
- `CatalogRerankProvider` + `createRerankProviderFromRuntimeConfig`：按 `endpointType === "openai_rerank"` 创建
- ai-center / engine DI：`LlmProviderModule` provide `RerankPort`
- 超时 / 4xx / 5xx → `LlmProviderError`

### 4.3 请求/响应适配（仅 adapter 内）

```json
{ "model": "qwen3-rerank", "query": "...", "documents": ["..."], "top_n": 10 }
```

返回 `results[].index` + `relevance_score` → contracts `relevanceScore`。

### 4.4 设计约束 / 扩展点

- **约束**：`RerankPort` / contracts **不得**出现 Jina/Qwen/DashScope 专有字段名；HTTP DTO 仅存在于 llm-core adapter
- **扩展点**：新增 Cohere/BGE/Jina = 新 provider 实现 + catalog `endpoint_type`，kb-core 零改
- **反模式**：在 kb-core 直接 `fetch` DashScope URL；把 rerank 塞进 `LlmProviderPort.chat`

## 7. 风险

- DashScope key 与 Doubao embed / 其它 vendor 凭据分离——均走 catalog 租户 provider，勿混用 env
- `qwen3-vl-rerank` 需原生 API，误用 `openai_rerank` 会失败 → 留给 W4.4
- score 区间不统一 → W2.2 clamp 前做 min-max 或 sigmoid 文档化
- 不同协议不能靠后缀兼容：`openai_rerank` 与未来的 DashScope native rerank 必须使用不同 endpoint type / adapter / wire DTO
- 工作空间专属 endpoint 被写入系统初始化目录，会使所有使用该 seed 的环境默认指向同一工作空间；跨环境部署必须在 catalog 中覆盖地址，并确认 API Key 对该工作空间有权限
- 文档数上限不等于 token 预算一定满足；候选数、文本长度和 query 长度必须共同计算
