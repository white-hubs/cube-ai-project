# W4.6 — 摄入失败任务管理（后置）

## 1. 决策

2026-08-11 产品优先级再次确认：在独立失败任务管理端缺失期间，upload/reindex/preview 先采用同步产品路径，`INGESTION_ASYNC_ENABLED` 默认 false；独立失败任务管理端暂不实现。W3.3 异步能力代码继续保留自动限次重试、MySQL `failed` 终态、错误信息和重启恢复，本项只承接未来异步重新启用后的人工运营闭环，不得被解释为删除底层失败保护。

## 2. 后续准入条件

- 存在明确的 KB 管理端入口和 owner；
- 明确谁可以按 tenant 查询、重放和取消失败任务；
- 确定 BullMQ failed job、`document_import_job` 与 document 状态的权威关系和留存期；
- 定义重放幂等键和 generation 水位规则，旧任务不得覆盖新 generation；
- 有 queue depth、oldest age、retry/failed 指标和告警接收方。

## 3. 后续实现范围

- tenant-scoped 失败任务列表/详情，展示 documentId、importJobId、attempts、错误类别和时间；
- 可重试/不可重试错误分类，供应商限流/超时与永久契约错误分离；
- 带 jitter 的有界 backoff；
- 人工重放/取消接口与审计记录；
- BullMQ/MySQL 状态对账和过期清理；
- runbook、权限测试及真实 Redis/MySQL 故障注入。

## 4. 风险

- 重放若生成错误的 jobId 或绕过 `active_generation_job_id`，可能让旧任务覆盖新索引；
- 严格 readiness 若绑定整个 ai-center，Redis 故障可能连带 Agent/Flow，应优先采用 KB domain degraded health；
- 未定义留存期会使 BullMQ failed set 和 MySQL 错误记录持续增长；
- 错误分类误判会造成无意义重试或过早终止。
