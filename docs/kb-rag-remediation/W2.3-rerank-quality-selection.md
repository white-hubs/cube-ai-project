# W2.3 — Rerank 后质量筛选、多样化与动态 TopK 落地方案

> 状态：`implemented / external-validation-incomplete`
> 日期：2026-08-11
> 范围：仅 `packages/kb/core` 检索链路、本目录内计划/验收文档及 deployment `.env.example` 的注释模板；不改变 ACL、租户、摄入、数据库 schema、Redis 或 Flow。
> 前置：W1.4 golden 评测、W2.2 模型精排已存在。本文最初先于实现冻结范围；当前实现已通过本地类型检查和离线全量测试，但尚无真实模型 E3 与生产流量证据，交付状态仍以 DELIVERY-MATRIX 为准。

## 1. 结论先行

本次不能把单条 `rankScore=0.81917` 解释成“检索质量 81.917 分”，也不能仅凭一次查询断言已经达到“80 以上”。`qwen3-rerank` 返回的是本次请求中 query-document 的相关性排序分；阿里云官方明确提示该分值是相对值，不适合跨请求直接比较。因此：

- **代码合入主门阀**：同一冻结 fixture 上 `nDCG@5 >= 0.80` 且不低于 before；critical query `Hit@3=1`；重复 section、弱结果泄漏、fallback、动态 TopK 等行为门阀全部通过。
- **真实能力启用主门阀**：在预登记 E3 真实/脱敏语料上，以人工相关性标注计算 `nDCG@5 >= 0.80`，并同时满足 critical `Hit@3=1`、无答案误召回、p95/p99、错误率、fallback 率和费用预算。E1 合成 fixture 只能阻止代码退化，不能证明线上达到 80。
- **本次完整实现**：独立 rerank 阈值、结构化 rerank 输入、标准编号归一化、精确匹配保留、内容去重、section 配额、向量 MMR、多文档语义保持和动态 TopK。所有策略一次落地，不按 P0/P1/P2 拆分。

## 2. 已核实事实、推测与工程判断

### 2.1 已核实事实

1. 当前 [`model-rerank.ts`](../../packages/kb/core/src/modules/vector-store/services/model-rerank.ts) 已将普通 chunk 构造成 `file/section/headers/keywords/content` 结构化输入；`table-row-window` 的 content 优先使用 `embeddingText`。这是已实现事实，不得再按“模型只看到正文”重复改造。
2. 当前模型成功时会把 `modelRerankScore` 写入 `rankScore`，并使用独立的 `RETRIEVAL_RERANK_MIN_SCORE`；fallback 才使用 pre-rank 与普通阈值。非同分候选的最终顺序完全由模型分决定，原召回 `score` 只在模型分完全相等时作为 tie-break。这解决了阈值混用，但引入“模型近似误差覆盖强召回/标题信号”的已知风险。
3. 当前返回项会在 `buildSearchItem` 中聚合同 section 的相邻 chunk；筛选发生在聚合之前。因此两个不同 chunk 可能返回高度重叠甚至近似相同的展开文本。关闭 rerank 的实测样例中，chunk `19` 与 `20` 同属“5.2 用户用电安全自查”，占据 Top5 两席。
4. 当前 [`qdrant-vector.repository.ts`](../../packages/kb/core/src/modules/vector-store/infrastructure/qdrant/qdrant-vector.repository.ts) 已有批量 `getVectorsByPointIds`，可一次取回候选 dense vectors；实现 MMR 不需要改 Qdrant schema 或新增跨领域依赖。
5. 当前 W1.4 已计算 Hit@k、MRR、nDCG；现有合成 fixture 的 Hit@3/MRR 基线为 1.0。它适合回归门阀，但由于数据是合成/桩实现，不能证明真实模型收益。
6. 已开启 rerank 的实测日志显示：16 个候选调用 `qwen3-rerank`，上游 HTTP 200，返回 16 个结果；这只能证明调用成功。该样例中 top1 仍为 chunk `6`，低相关的 chunk `13` 仍以 `0.625551` 返回，说明“调用成功”不等于“尾部质量已达标”。
7. 事实问答反例 `证实方法有哪些？` 中，`chunk-5`（范围声明，只提到“证实方法”）以 `0.862109` 排第一，`chunk-25`（“8 证实方法”，列举 8.1/8.2/8.3）以 `0.854213` 排第二，差值 `0.007896`。输入已包含二者 section/content，因此这是可观察的 Top1 误排，不是标题漏传；它同时证明“分数 > 0.8”不等于答案正确。

### 2.2 尚未被数据证明的推测

- `0.65` 能否作为所有业务查询的长期 rerank 下限，尚无 E3 标注集证明。本次若使用它，只能是**可回滚的保守初值**，必须由 E3 校准。
- section 配额为 1 在当前标准文档样例中能消除重复，但在超长 section 或列表拆成多个互补 chunk 时可能损失召回。因此它必须可配置，并由 exact-match 保留与 MMR 共同缓解。
- MMR 能提高内容多样性，但多样性不等于相关性；`lambda` 过低会把“不同但更不相关”的结果抬高。
- 对近似分候选融合 pre-rank、标题或答案完整性信号可能修复当前反例，但权重、分差窗口和适用 query 类型尚无标注集校准；不得把 `0.007896`、章节名或 chunkId 写成生产规则。

### 2.3 工程判断

- **不接受**“只加 rerank 就能达到 80”的前提。reranker 只能重排已召回候选，无法找回候选集之外的正确答案。
- **不接受**固定返回请求 `topK` 个结果。没有足够强候选时返回更少，优于用低相关结果补满；API 的 `topK` 应解释为上限而不是最低数量。
- **不接受**把普通相似度阈值直接用于模型分。fallback 分和 rerank 分必须有独立默认阈值，响应中仍保留原 `vectorScore` 供诊断。
- **不接受**“模型分最高即一定是直接答案”。默认问答 instruct 是模型目标而非确定性约束；当前系统必须用评测门阀约束 Top1，并为模型近似误差保留通用纠偏设计空间。
- **不接受**把显式发送阿里云默认 `instruct` 当作本次误排修复。官方契约说明省略即默认问答检索；当前不发送该字段。只有改变排序任务时才另立方案和 E3。

## 4. 冻结后的目标流水线

```text
hybrid/lexical recall
  → 既有质量过滤与规则 pre-rank
  → 公平分配 rerank candidate budget
  → 生成结构化、编号归一化的 rerank 文本
  → qwen3-rerank（失败则保留 pre-rank 并标记 fallback）
  → 按分值来源选择独立阈值
  → 最多给 1 个 normalized exact-match 候选提供默认阈值豁免
  → normalized content fingerprint 去重
  → 每 document + section 配额
  → dense-vector MMR 多样化
  → dynamic TopK（最多 topK，不以弱结果补满）
  → 既有 section context 聚合与响应投影
```

选择顺序不是任意的：exact-match 在阈值阶段保留，防止标准编号或完整标题因为模型分漂移被误杀；内容与 section 去重在 MMR 前执行，避免明显重复浪费向量比较；MMR 在最终 topK 前执行，才能改变选择集合而不只是改变展示顺序。

## 5. 具体改造方式

### 5.1 分离分值与阈值

为 rerank 后候选增加内部字段 `modelRerankScore?: number`：

- 模型成功返回：`rankScore=modelRerankScore`，默认使用 `RETRIEVAL_RERANK_MIN_SCORE`。
- 模型关闭或调用失败：没有 `modelRerankScore`，继续使用既有 `rankScore` 和 `RETRIEVAL_DEFAULT_SIMILARITY_THRESHOLD`。
- 某个被送入模型的候选缺失返回分：按 rerank 分 0 处理，不允许偷偷回到宽松 fallback 阈值。
- `vectorScore` 不变；不把 rerank 分覆盖为 vector 分。
- 请求显式传入 `similarityThreshold` 时保持当前 API 兼容语义，作为该次请求的最终阈值覆盖；默认值才按分值来源分离。

当前限制：上述方式会让任何非零模型分差直接决定顺序，即使差值极小且 pre-rank/标题信号相反。该限制已由 §2.1 的“证实方法”反例证实；后续通用融合或近似并列策略必须先补方案、标注和门阀，不能在本工作项中写死权重。

建议初始配置如下。数字是可测试的工程初值，不是已经验证的最优参数：

| env | 默认 | 作用 | 事实/风险 |
| --- | ---: | --- | --- |
| `RETRIEVAL_RERANK_MIN_SCORE` | `0.65` | 模型成功后的绝对下限 | 当前样例会过滤 `0.625551`；E3 前不能宣称普适 |
| `RETRIEVAL_DIVERSIFICATION_ENABLED` | `false` | 开启 exact 默认阈值豁免、去重、section 配额和 MMR | 会改变返回数量；按 G0-9 在 E3 前默认关闭，目标环境显式开启验证 |
| `RETRIEVAL_MMR_LAMBDA` | `0.75` | 75% 相关性、25% 多样性 | 越低越偏多样，必须 E3 校准 |
| `RETRIEVAL_MAX_CHUNKS_PER_SECTION` | `1` | 单文档同 section 最多返回数 | 长 section 可能损失互补内容 |
| `RETRIEVAL_EXACT_MATCH_RESERVE` | `1` | 最多一个精确命中可绕过默认阈值 | 不是“所有精确命中最多返回一个” |

### 5.2 结构化 rerank 输入

送给模型的是内部构造文本，不改写存储的原文，也不改变 API 返回：

```text
[file] 用电检查规范.pdf
[section] 2 规范性引用文件
[keywords] 用电安全, 检查
[content]
下列文件……GB/T 13869 用电安全导则……
```

字段为空时不输出对应行；`table-row-window` 的 content 仍优先使用 `embeddingText`。这样做的原因是当前普通 paragraph 缺少文件与层级上下文，模型只能看到局部正文。结构化字段来自现有 payload，不新增数据库或摄入字段。

### 5.3 标准编号归一化

仅在 rerank 输入、exact-match 比较和去重 fingerprint 中归一化，不篡改 source text。例如：

| 原始 OCR 文本 | 比较文本 |
| --- | --- |
| `GB / T1 3 8 6 9` | `GB/T 13869` |
| `DL / T1 4 7 6` | `DL/T 1476` |
| `GB5 0 0 1 6` | `GB 50016` |

实现只处理明确的 `GB[/T]`、`DL[/T]` + 被空格拆散的数字模式；不能对普通自然语言全局删除空格，避免制造误匹配。

### 5.4 exact-match 保留

将 query 与候选结构化文本做 Unicode 小写、标点/空白折叠和标准编号归一化。满足候选包含完整 normalized query 时进入 exact reserve：

- 最多 `RETRIEVAL_EXACT_MATCH_RESERVE=1` 个候选可以凭 exact 信号绕过默认阈值；其他 exact 候选如果正常通过阈值，仍可参与后续去重、section 配额与 MMR，不能被误删。
- exact reserve 可以绕过默认 rerank 分阈值，但不能绕过租户、ACL、document filter、摄入质量过滤或请求显式阈值。
- 目的不是“关键词永远第一”，而是防止标准号、产品名、完整标题这类强信号被模型分漂移误杀。

### 5.5 内容去重与 section 配额

1. 对 normalized rerank 文本生成稳定 fingerprint，完全相同只保留高分候选。
2. 对有 `sectionId` 的候选，以 `documentId + sectionId` 计数，默认最多 1 个；没有 sectionId 的候选不互相错误合并。
3. 排序与 tie-break 必须稳定：`rankScore desc → 原候选顺序 → id`。

这一步直接处理当前 chunk `19/20` 同 section、聚合后正文近似重复的问题。它不尝试做昂贵的 LLM 去重。

### 5.6 dense-vector MMR

通过现有 `getVectorsByPointIds` 一次批量读取进入选择阶段的候选 dense vectors，采用 cosine similarity：

```text
MMR(candidate) = λ × normalizedRelevance
               - (1 - λ) × maxCosineSimilarity(candidate, selected)
```

- exact reserve 先放入 selected，再对剩余候选做 MMR。
- relevance 使用本阶段 `rankScore`，在当前候选集合内 min-max 归一化；全部同分时视为 1，保持稳定 tie-break。
- 候选少于 2、开关关闭、向量缺失或批量读取失败时，退化为稳定相关性排序；请求不能因多样化附加能力失败。
- 不增加逐候选 Qdrant 请求；一次批量 retrieve 的额外延迟和流量必须进入 E3 p95/费用记录。

### 5.7 动态 TopK

`topK` 改为最大返回数。阈值、去重、section 配额和 MMR 后只剩 3 个合格结果时返回 3 个，不从阈值以下补 2 个。空候选仍快速返回空数组，不触发无意义模型调用。

多文档接口保持现有契约：rerank 仍全局只调用一次，候选预算继续保证文档代表性，最终对每个 document 分别应用其 `spec.topK` 上限，并按请求 document 顺序投影。

## 6. 当前样例的预期行为

请求：

```json
{"query":"用电安全导则","documents":[{"documentId":"2086630204986372098","topK":5}]}
```

本次实测可验证的 before：

- rerank off：chunk `19` 和 `20` 同 section，占用两个名额。
- rerank on：chunk `6` 仍为 top1；chunk `13` 分数 `0.625551` 仍被返回。

在 `RETRIEVAL_MODEL_RERANK_ENABLED=true` 且 `RETRIEVAL_DIVERSIFICATION_ENABLED=true` 时，按本文初值的确定性预期：

- chunk `6` 因完整命中“用电安全导则”且模型分 `0.81917` 被保留；top1 不应退化。
- chunk `13` 低于默认 rerank 下限 `0.65`，若不满足 exact reserve，应被过滤。
- 同一 `documentId + sectionId` 的 chunk `19/20` 最多保留高分者。
- 若最终只有 4 个合格且不重复的候选，响应返回 4 个，而不是补满 5 个。

这些是输入分值和规则可推导的行为，不等于对所有查询质量提升的统计证明。

第二个必须保留的事实问答回归样例：

```json
{"query":"证实方法有哪些？","documents":[{"documentId":"2086630204986372098","topK":5}]}
```

- 相关性标注：`chunk-25` 是直接答案，`chunk-5` 仅为主题/范围提及。
- 当前真实模型结果：`chunk-5=0.862109`、`chunk-25=0.854213`，Top1 错误。
- 目标不是写死 chunk，而是把该对映射成 fixture 中的 graded relevance，要求任何通用方案在相同候选集上把直接答案排在主题提及之前。
- 如果 parser/chunker 改变 chunkId，fixture 应通过稳定语义标签/期望文本或新的数据集版本迁移，不能把生产逻辑绑定旧 ID。

## 9. 真实数据启用门阀：“质量 80”的严格定义

启用前冻结如下实验协议，结果出来后不得换口径：

1. 数据集按 query 类型分层：精确标准号/标题、事实问答、流程问答、直接答案与仅主题提及 hard-negative、跨 section、no-answer、critical 安全/法规；来源、版本、标注人和冲突仲裁有记录。
2. 每条 query 标注相关 chunk 的 graded relevance（建议 0/1/2/3），主指标为 macro `nDCG@5`。
3. **通过线**：after `nDCG@5 >= 0.80`，且相对 before 非劣；critical `Hit@3=1`；no-answer false recall 不高于预登记上限。
4. 报告配对 bootstrap 95% 区间；样本规模不得用当前“≥10 smoke”冒充统计充分性。
5. 同时报告 p50/p95/p99、rerank 错误率、fallback 率、Qdrant vector retrieve 额外耗时、模型调用量/token/费用。任一预算超标即不默认开启。

若没有 E3 标注数据，只能合并默认关闭、可回滚的代码，不能宣称“质量已达到 80”，也不能把多样化默认开启。

## 10. 成本、偏差与被忽略变量

- **候选召回上限**：正确 chunk 不在 rerank input 中，后续任何阈值/MMR 都无能为力；必须同时观察 recall@inputN。
- **OCR 质量**：`GB / T1 3 8 6 9` 说明源文本有字符间空格；规则只覆盖有限标准号，正文 OCR 错字仍影响 embedding 和 rerank。
- **标注偏差**：只用这一份“用电检查规范.pdf”会高估对标准文档的效果，不能外推到表格、FAQ、图片或多语言文档。
- **聚合偏差**：评测若按原 chunkId 标注，而响应文本已做 section 聚合，可能低估/高估实际可回答性；E3 必须同时保存命中 chunkId 与最终投影文本。
- **多样化成本**：每次请求增加一次候选向量批量 retrieve 和 O(topN²) 小规模余弦计算；topN 默认 50 时可控，但必须测 p95。
- **阈值漂移**：模型版本、候选数量和语料变化会改变分数分布；阈值不能“一次标定永久有效”。
- **exact-match 偏差**：query 在“规范性引用文件”中完整出现，不代表该 chunk 能回答用户潜在问题；默认阈值豁免限 1，其他 exact 候选仍须正常过阈值，避免低分引用条目靠关键词豁免垄断。
- **返回数变化**：dynamic TopK 会让前端看到少于请求值的 items；当前响应 schema 是数组且无“必须满 topK”契约，但调用方应按上限处理，不能假定固定长度。
- **模型近似分误差**：当前最终排序在非同分时只看模型分；非常小的模型差距也会覆盖 RRF、标题和 lexical 强信号。任何融合权重、margin 或答案结构特征都必须通过冻结 before/after 校准，不能从单个反例外推。
- **切块完整性**：正确章节可能在句子中间截断；模型可能因此降低答案完整性判断。应同时评估 parser/chunker，而不能把所有误排都归因于 reranker。
