## 1. 背景与问题

现状唯一「评估」是 [`retrieval-evaluation.test.ts`](../../packages/kb/core/src/modules/vector-store/services/retrieval-evaluation.test.ts)：4 个手写场景 + Fake embedding/Qdrant，断言 MRR=1。

本波交付**可重复的离线 golden 门禁**，不是完整 RAGAS / Hit Testing UI（那是 W4.2）。本计划区分指标单测、生产编排契约、真实数据面和 live 实验，定义见 [EVALUATION-STRATEGY.md](./EVALUATION-STRATEGY.md)。

## 2. 目标 / 非目标

**目标**

- 固化 golden set（JSON）：query → 期望 `documentId` / `chunkId`（可多相关 + grade）
- 指标：`hit_rate@k`、`MRR`、`nDCG@k`（k=1/3/5）
- 两种模式 + **明确门禁规则**（见 §4）
- 输出机器可读结果到 `.tmp/kb-eval/`（gitignore）
- 在 W1.1/W1.2 等行为改动前登记 E1 before 基线
- 为 W2.2 提供改前/改后对比入口；真实收益仍须 E3

**非目标**

- RAGAS（需 LLM judge）
- 检索测试前端 UI
- live 指标进 CI 阻断（波动大）

## 4. 门禁规则（选定）

| 模式 | 何时跑 | 是否阻断 CI | 失败判定 |
| --- | --- | --- | --- |
| **metrics unit（E0）** | 每次 `bun test` | **是** | 指标公式错误或固定样例不符 |
| **fixture（E1）** | 每次 `bun test` | **是** | 必须经过 RetrievalService；宏平均或 critical case 低于登记基线即 fail |
| **live** | `KB_GOLDEN_LIVE=1` | **否**（仅本地/夜间） | 打印对比；允许 ±2% 波动提示，不 fail CI |

- 修改检索逻辑导致 fixture 基线下降：必须在同 PR 更新基线常量，并在 PR 说明「为何接受下降」或先修回归
- 改阈值 / 开 rerank（W2.2）：PR 必须附 fixture（及可选 live）前后数字

### cases.v1.json 形态

```json
{
  "version": 1,
  "cases": [
    {
      "id": "clause-normative-refs",
      "query": "条款",
      "profileHint": "entity-lookup",
      "relevant": [
        { "documentId": "doc-a", "chunkId": "chunk-1", "grade": 2 },
        { "documentId": "doc-a", "chunkId": "chunk-2", "grade": 1 }
      ],
      "k": [1, 3, 5]
    }
  ]
}
```

首版 ≥10 条，覆盖 semantic / entity / navigation / table；至少 3 条来自真实 PDF 场景的**脱敏**合成。该数字仅为 smoke 覆盖下限，不得用于证明统计收益；E3 规模与分层由 EVAL-01 决定。

## 5. 指标定义

- **hit_rate@k**：top-k 是否命中任意 `grade>0`
- **MRR**：第一个相关结果排名倒数，未命中 0
- **nDCG@k**：标准 DCG/IDCG

聚合：cases 宏平均。

### 5.1 设计约束 / 扩展点

- **约束**：`eval/metrics` 与 RetrievalService **解耦**；仅 E0 metrics 单测可注入 fake hits，E1 fixture runner 必须调用 RetrievalService，并只在 store/provider 边界注入确定性 adapter
- **扩展点**：`cases.v1.json` 带 version；W2.2/W4.3 只追加 cases 或升 version，不改指标公式语义
- **反模式**：把 golden 断言嵌进 controller 集成测导致无法做 CI 基线常量
