## 2. 目标 / 非目标

**目标（二选一，用 W1.4 live + 慢查询选定）**

### 方案 A（**已选定**）：MySQL ngram FULLTEXT

- 对核心文本列建 ngram FULLTEXT
- `searchLexicalChunks` 在 `LEXICAL_FULLTEXT_ENABLED=true` 时改 `MATCH ... AGAINST`
- **必须**定义与现有 `lexicalScore * LEXICAL_SCORE_WEIGHT(0.08)` 兼容的归一化
- 默认 **off**：保持 W1.1 LIKE 路径；开启需灰度 / golden 依据（G0-9）

### 方案 B：弱化 MySQL 词法，强化 Qdrant sparse（未选）

- lexical 仅极小兜底或删除
- 依赖模型 sparse + RRF

**A/B 决策**：选 **A**。理由：现有 hybrid 仍依赖 MySQL 词法腿；ngram FULLTEXT 可渐进替换 LIKE 扫描，无需先改 Qdrant sparse 管线；签名稳定、可 flag 回滚。

**非目标**：自建 ES（除非 A/B 证明必要）

## 3. 方案 A 设计细节（必须写清）

### 3.1 字段映射（现有 9 字段）

| 现字段 | FULLTEXT 策略 |
| --- | --- |
| text_content | 主索引列 |
| embedding_text | 主索引列 |
| heading_path | 主索引列 |
| keywords_text | 主索引列（高权语义由归一化后短字段/旧权重表体现，不另造权重） |
| headers_text | 主索引列 |
| sheet_name | **保留 LIKE** OR 兜底 |
| property_namespace | **保留 LIKE** OR 兜底 |
| start_time / end_time | **保留 LIKE**（时间码短文本，FULLTEXT 收益低） |

选定默认：**5 个主文本列 FULLTEXT + 时间/namespace/sheet 短字段保留 LIKE OR**，避免召回语义回退。

### 3.2 分数归一化（必须）

`MATCH...AGAINST` 分数量纲 ≠ 现 JS 加权分。另一个必须先处理的问题是：若 SQL 只按 `ft_raw_score` 截断，短字段 LIKE-only 命中可能全部为 raw=0，并在进入 JS bonus 前被随机/顺序性淘汰。因此候选生成改为两个 producer：

1. FULLTEXT 主文本候选 top `N_ft`。
2. 短字段 LIKE 预评分候选 top `N_short`。
3. `UNION ALL`/两次查询后按 chunkId 去重，再在 JS 中归一化、叠加 bonus 和取 topK。

`N_ft + N_short` 受统一 candidate budget 控制，分配比例由 E1/E3 数据决定；不得用任意默认比例宣称完整召回。

落地公式（见 `lexical-fulltext-score.ts`）：

1. SQL 取 FULLTEXT 候选并选出 `ft_raw_score = MATCH(...) AGAINST (? IN BOOLEAN MODE)`；另取短字段 LIKE 预评分候选
2. JS：对窗口内 raw 做
   - `t_i = log1p(max(0, raw_i))`
   - 若 `max(t)=min(t)`：凡 `t>0` → `maxJsComparable`，否则 `0`
   - 否则 min-max：`((t_i - min) / (max - min)) * maxJsComparable`
3. `maxJsComparable` = Σ `LEXICAL_FIELD_WEIGHTS[f].exact`（**仅 FULLTEXT 五主列**）
4. 再叠加短字段 LIKE bonus（同表 `LEXICAL_FIELD_WEIGHTS` 的 exact/term）
5. 返回字段名仍为 `lexical_score`；上游再乘 `LEXICAL_SCORE_WEIGHT`
6. **禁止**把 raw MATCH 直接当 hybrid 相似度

### 3.3 Migration 落点

- 文件：`packages/kb/core/migrations/V003__document_chunk_fulltext.sql`（接 W3.5 的 `V002__incremental_reembed.sql`）
- ngram parser：`WITH PARSER ngram`；`ngram_token_size` 为 **server 设置**，migration **不**改全局变量
- 大表 `ALGORITHM=INPLACE` 可行性需运维评估（见 migration 注释）
- 回滚：`ALTER TABLE document_chunk DROP INDEX ft_document_chunk_lexical;`
- 幂等：MySQL 对 FULLTEXT `IF NOT EXISTS` 支持不一；本脚本为 **one-shot ADD**；重复执行在索引已存在时失败，按「已应用」处理

外部事实：MySQL 官方说明首次为缺少用户定义 `FTS_DOC_ID` 的 InnoDB 表增加 FULLTEXT 可能重建表；`ngram_token_size` 是服务端启动配置。上线前必须按 [ROLLOUT-AND-MIGRATION.md](./ROLLOUT-AND-MIGRATION.md) 在生产等规模副本做 DDL/空间/并发 DML dry-run，不能把 `INPLACE` 当成无风险结论。

### 3.4 设计约束 / 扩展点

- **约束**：归一化公式文档化；权重仍引用 W1.1 `LEXICAL_FIELD_WEIGHTS` 语义，禁止第三套权重表
- **扩展点**：SQL 体可替换（LIKE → FULLTEXT），repository 对外 `searchLexicalChunks` 签名稳定；flag 默认 off
- **反模式**：把 MATCH 原始分直接当 hybrid 相似度与向量分相加
